SDA Commons Server Testing: JSON Schema¶

The module sda-commons-server-testing provides a JsonSchemaGenerator that generates JSON Schema Draft 2020-12 documents from Java types. Use it in tests to generate schemas for payload, request, or response models without maintaining a separate schema by hand. No additional JSON Schema module is needed.

The default generator reads Jackson, Jakarta Validation, and Swagger annotations from the model.

@JsonValue is not supported because of an issue in the underlying schema generator that can produce incorrect types. See victools/jsonschema-generator#528 for details.

Usage¶

Add Server Testing to the test dependencies. The sda-commons-bom manages its version.

1
2
3
dependencies {
  testImplementation 'org.sdase.commons:sda-commons-server-testing'
}

Generate a schema for one type¶

Create the default generator and pass the root Java type to generate:

1
2
3
4
5
import com.fasterxml.jackson.databind.node.ObjectNode;
import org.sdase.commons.server.testing.jsonschema.JsonSchemaGenerator;

ObjectNode schema =
    JsonSchemaGenerator.defaultGenerator().generate(CustomerCreated.class);

The result contains the Draft 2020-12 $schema identifier. Reusable object schemas are stored under $defs.

Generate a schema catalog for multiple types¶

Pass an Iterable of Type instances to generate one catalog. The catalog references every root type in oneOf and stores reusable object schemas under $defs. Duplicate roots are ignored. If only one distinct root remains, the result uses the standalone schema shape without oneOf.

import com.fasterxml.jackson.core.type.TypeReference;
import com.fasterxml.jackson.databind.node.ObjectNode;
import java.lang.reflect.Type;
import java.util.List;
import org.sdase.commons.server.testing.jsonschema.JsonSchemaGenerator;

Type customerCreatedList = new TypeReference<List<CustomerCreated>>() {}.getType();

ObjectNode schemaCatalog =
    JsonSchemaGenerator.defaultGenerator()
        .generate(List.of(CustomerCreated.class, CustomerUpdated.class, customerCreatedList));

To add a root-level $id, pass it as the second argument:

1
2
3
4
5
String schemaId = "https://schemas.example.com/customer-events/1.2.0";
ObjectNode schemaCatalog =
    JsonSchemaGenerator.defaultGenerator()
        .generate(
            List.of(CustomerCreated.class, CustomerUpdated.class, customerCreatedList), schemaId);

The generator writes the supplied string unchanged and does not derive or add a version. Passing null omits $id.

Use TypeReference when a root type contains generic type information that must be retained, such as List<CustomerCreated>.

A consumer can select a specific object schema through its definition reference, for example schemas.json#/$defs/CustomerCreated.

package org.sdase.commons.server.testing.jsonschema;

import io.swagger.v3.oas.annotations.media.Schema;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import java.time.Instant;

@Schema(title = "Customer created", description = "Customer creation event")
public class CustomerCreated {
  @NotBlank
  @Schema(description = "Customer identifier", example = "customer-42")
  private String customerId;

  @NotNull private Instant occurredAt;

  public String getCustomerId() {
    return customerId;
  }

  public Instant getOccurredAt() {
    return occurredAt;
  }
}

{
  "$schema" : "https://json-schema.org/draft/2020-12/schema",
  "$ref" : "#/$defs/CustomerCreated",
  "$defs" : {
    "CustomerCreated" : {
      "type" : "object",
      "properties" : {
        "customerId" : {
          "type" : "string",
          "minLength" : 1,
          "pattern" : "^.*\\S+.*$",
          "description" : "Customer identifier",
          "examples" : [ "customer-42" ]
        },
        "occurredAt" : {
          "type" : "string",
          "format" : "date-time"
        }
      },
      "required" : [ "customerId", "occurredAt" ],
      "title" : "Customer created",
      "description" : "Customer creation event"
    }
  }
}

The default configuration provides the following behavior:

Model input JSON Schema behavior
Jackson annotations Apply property names, order, required markers, transformed subtypes, and enum values
Jakarta Validation annotations Apply supported validation constraints and mark fields with non-null constraints as required
Swagger annotations Apply supported schema metadata and constraints, including titles, descriptions, and examples
